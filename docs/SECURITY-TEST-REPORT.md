## 2. 测试中发现并修复的问题

### 2.1 SSRF 绕过：IPv6 字面量方括号（严重）

- **现象**：`new URL('http://[::1]/').hostname` 返回 `[::1]`（带方括号），原私网判断未剥离，导致 `::1` 被当作公网地址放行。同类问题包括 IPv4-mapped IPv6 十六进制写法 `::ffff:7f00:1`。
- **影响**：已授权的配置接口可创建指向本机/内网服务的监控项，探测结果可能被用于内网探测。
- **修复**：在 SSRF 校验与 IP 判断中统一剥离方括号；对 `::ffff:` 后的十六进制映射展开为 IPv4 再判断；拒绝纯数字与十六进制混淆主机名。
- **验证**：测试覆盖 `127.0.0.1`、`0177.0.0.1`、`127.1`、`0x7f.1`、`2130706433`、`[::1]`、`[::ffff:7f00:1]`、`[::ffff:127.0.0.1]`、`169.254.169.254` 等，全部被拒绝。

### 2.2 告警去重失效风险：动态错误签名（中等）

- **现象**：原签名直接拼接原始错误文本，网络错误文案微小变化（含 IP、端口、随机数）会生成新签名，绕过冷却窗口形成告警风暴。
- **修复**：新增 `errorClass()`，将错误归一化为 `timeout` / `probe-missing` / `dns` / `tls` / `network` / `http` 六类，签名由 `status + errorClass` 组成。
- **验证**：测试中用两条文案完全不同但同属 network 的错误连续触发，告警次数保持 1；切换为 timeout 类别后才产生第 2 次通知。

### 2.3 鉴权边界：令牌中间空格（低）

- **现象**：测试发现 HTTP 标准 Headers API 会剥离头部值首尾空白，因此 `Bearer <token> `（尾部空格）会被接受。该行为符合 RFC 7230 对 OWS 的处理，不构成真实绕过。
- **修复**：仍增加防御性校验，令牌内部含任意空白字符即拒绝，进一步收紧格式。
- **验证**：`Bearer Secr3t Admin Token` 返回 401。

### 2.4 测试辅助代码缺陷（非产品问题）

- 初版测试辅助函数在读取响应时重复消费 body，导致假失败；已修正为仅在非预期状态时读取。不影响产品代码。

## 3. 静态扫描结果

扫描 `eval(`、`new Function`、`innerHTML`、`outerHTML`、`document.write`、`child_process`、`exec(`、`spawn(` 等模式：

- 产品源码中**零命中**。
- 唯一命中为安全测试自身的断言字符串和国内探针脚本对 `process.env` 的正常读取。
- 项目无 `package-lock.json` 与第三方运行时依赖，供应链攻击面极小。

## 4. 残余风险与说明

| 风险 | 说明 | 缓解措施 |
|---|---|---|
| DNS rebinding（TOCTOU） | SSRF 校验时的 DNS 解析与实际连接之间存在时间窗，Workers 环境无法把连接固定到已校验 IP | 禁止 IP 字面量与混淆写法、DNS 解析后校验、拒绝跟随重定向、限制仅 http(s)；剩余风险较低 |
| 告警最终投递 | 邮件依赖 Resend、Webhook 依赖用户端点 | 工具保证按策略触发与发送，Webhook 带 HMAC 签名；建议接收方验签并设置重试 |
| KV 最终一致性 | 多探针并发回传时短暂读到旧值 | 完整轮次才提交历史；告警状态机以单监控项为粒度，避免跨项干扰 |
| 配置接口爆破 | 无内置速率限制 | 由 Cloudflare Rate Limiting 规则或 WAF 在边缘层限制 `/api/*` 请求频率 |
| Demo 版本 | 阶段 A 为单文件演示，CSP 含 `unsafe-inline` 用于内联脚本 | 生产部署使用阶段 B（`src/index.mjs`，main 已指向该文件） |

## 5. 结论

在自动化覆盖的范围内，UptimePulse 未发现未修复的已知漏洞或逻辑漏洞。SSRF、鉴权越权、XSS、告警去重失效等核心风险均有对应测试用例守护。残余风险已在上文如实标注，并给出缓解建议。
